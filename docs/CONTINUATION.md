# Продолжение разработки

Этот файл — точка передачи проекта на другой компьютер. Он описывает текущее
состояние, решения и следующий набор задач, без необходимости восстанавливать
контекст из переписки.

## Что уже работает

- `main.py` — движок распознавания рук на OpenCV + MediaPipe.
  - раскрытая ладонь → Quas / `Q`;
  - кулак → Wex / `W`;
  - V-знак → Exort / `E`;
  - две раскрытые ладони → Invoke / `R`.
- `app.py` — интерфейс Material 3 на Flet: выбор камеры, предпросмотр,
  отображение жеста и последовательности, редактирование биндов и безопасный
  переключатель отправки клавиш.
- По умолчанию приложение находится в режиме предпросмотра. Нажатия в активное
  окно отправляются только после включения переключателя или `--send-keys`.
- `config.example.json` хранит номер камеры, тайминги и бинды.
- GitHub Actions в `.github/workflows/windows-release.yml` собирает Windows EXE
  и прикрепляет ZIP к указанному существующему релизу.

## Важное техническое решение

`flet` закреплён в `requirements.txt` на **0.27.6**. Не меняйте его на
неограниченную новую версию без адаптации `app.py`: Flet 1.x заменил точку
входа `ft.app()` на `ft.run()`, из-за чего первая Windows-сборка не запускалась.

## Запуск из исходников

### Windows

```powershell
git clone https://github.com/Aks1k642/invoker-hand-signs.git
cd invoker-hand-signs
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

### Linux

```bash
git clone https://github.com/Aks1k642/invoker-hand-signs.git
cd invoker-hand-signs
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

На Linux синтетический ввод через `pynput` рассчитан на X11/Xorg. В Wayland он
может быть заблокирован, хотя предпросмотр камеры продолжит работать.

## Выпуск Windows-версии

1. Обновить исходники и `CHANGELOG.md` на `main`.
2. Создать GitHub Release с новым тегом, например `v1.0.2`.
3. В **Actions → Build Windows release → Run workflow** указать этот тег.
4. Workflow запускается на `windows-latest`, собирает `InvokerHandSigns.exe`
   через PyInstaller и добавляет `InvokerHandSigns-windows-x64.zip` в релиз.
5. Скачать релиз и проверить камеру на реальном Windows-компьютере перед
   публикацией как стабильной версии.

## Что нужно проверить на реальном ПК

- Камера корректно выбирается из списка и открывается в Flet-предпросмотре.
- Одна и та же печать не повторяется без нейтрального положения рук.
- При включённой отправке клавиш `Q/W/E/R` приходят именно в активное окно.
- Dota 2 принимает такой ввод в тренировочном лобби. Некоторые игры могут
  игнорировать синтетические события, и это нельзя гарантировать кодом.
- Windows SmartScreen может предупредить о неподписанном EXE: сборка пока не
  имеет сертификата подписи кода.

## Приоритетный roadmap

### 1. Настройка жестов в интерфейсе

- вынести `hold_seconds` и `release_seconds` в ползунки UI;
- добавить кнопку сохранения `config.json`;
- добавить мастер калибровки камеры и дистанции до неё.

### 2. Удобство игры

- добавить профили биндов для разных раскладок;
- показать историю последних распознанных печатей;
- добавить звук или визуальную вспышку после успешного Invoke;
- отдельно продумать безопасный режим каста способности: наведение цели лучше
  оставить мыши, а не автоматически эмулировать клик.

### 3. Надёжность и тесты

- написать unit-тесты для `classify_single_hand()` и `GestureDebouncer`;
- записать короткие видеоклипы жестов для регрессионных проверок;
- протестировать Windows, Linux/X11 и Linux/Wayland отдельно;
- добавить обработку отсутствующей/отключившейся камеры в UI с кнопкой
  повторного поиска.

### 4. Дистрибуция

- добавить иконку приложения и сведения о версии в EXE;
- при необходимости собрать установщик, например Inno Setup;
- для распространения без предупреждений SmartScreen нужен сертификат подписи
  кода и отдельная процедура подписи в Windows workflow.

## Границы проекта

Программа предназначена для локальных экспериментов, тренировки и лобби.
Перед использованием в сетевых матчах следует самостоятельно проверить
актуальные правила игры и отношение античита к синтетическому вводу.
